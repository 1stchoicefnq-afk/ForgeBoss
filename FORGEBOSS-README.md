# ForgeBoss v0.1

**ForgeBoss is the autonomous engineering system. SiteBoss is the application ForgeBoss builds.**

This checkpoint deliberately stops polishing a custom generic coding agent.

## What is retained from the proven stack
- live GitHub control and exact-head binding;
- bounded read/write packets;
- Repair Rat as the proven fallback/reference executor;
- PostgreSQL validation;
- cost controls;
- Agency specialist routing;
- independent reviewer / Reality Checker;
- draft-only publication safety;
- Windows one-click control.

## What is now real upstream code
`SETUP-FORGEBOSS-ENGINES.cmd` installs official upstream packages into an isolated ForgeBoss runtime:

- OpenHands SDK/tools/workspace 1.22.1;
- mini-SWE-agent 2.4.6;
- Deep Agents 0.7.6;
- current OpenCode CLI, with the installed version recorded.

These are dependencies, not rewritten imitations.

## Why not copy whole repositories?
Using released packages keeps upstream bug fixes and dependency management separate. ForgeBoss wraps them with its authority/scope layer. Whole-repo vendoring would make upgrades harder and create needless maintenance.

## Promotion rule
Repair Rat remains the default until an upstream executor wins the SAME frozen SiteBoss workload on:
1. correctness;
2. tests;
3. scope adherence;
4. API cost;
5. elapsed time;
6. independent review.

No upstream executor gets GitHub merge/deploy authority.
