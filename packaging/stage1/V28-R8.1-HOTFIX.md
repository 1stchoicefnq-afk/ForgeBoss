# v28.1 R8.1 Docker/BOM hotfix

Observed on the owner's Windows machine:
- `TURN-ON-FORGEBOSS.cmd` began with UTF-8 BOM bytes, so cmd.exe attempted to execute `∩╗┐@echo off`.
- Stage-1 installer assumed Docker Desktop CLI existed only at `%ProgramFiles%\\Docker\\Docker\\resources\\bin\\docker.exe`; the owner's working Docker installation used a different location.

Hotfix rules:
- all shipped `.cmd` entrypoints are encoded without a BOM;
- Docker discovery checks machine/user Docker Desktop registry entries, common install roots and the current `docker.exe` command;
- machine-protected Program Files paths are accepted directly;
- user-writable Docker paths require a valid Authenticode signer containing Docker;
- install records exact Docker path, SHA-256 and size in `stage1-installed.json`;
- Start and VERIFY re-check that exact Docker identity;
- mini-SWE is given the pinned absolute Docker path through `MSWEA_DOCKER_EXECUTABLE`, which is a supported DockerEnvironment setting;
- no PATH-selected Docker executable is used after installation.

Native owner VERIFY remains required before paid P0.
